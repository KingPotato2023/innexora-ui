Conventions

Two non-negotiable rules that keep every Innexora page reading as part of the same family. When a page skips them it stops feeling editorial within seconds.

Pills, not dropdowns, for filters

filter UI

Every filter bar uses PillButtons variant="filter". Native <select> and HiddenFormSelect are reserved for forms where the user is editing a record — never for filtering a list.

Why: a pill row shows every option at a glance, the active value is one click away, and the brand-indigo "active pill" is uniform — the eye locks onto the current filter without scanning. Dropdowns hide options behind a click and make the active state harder to read.

Icons on every label, header, and message

icon convention

Every text element that names a thing — a field, a column, a section, a confirmation prompt — gets a Lucide icon. Sized so the icon never visually outweighs the text it labels.

Why: a glanceable icon roughly doubles "I know what this is" speed. After 100 hours in the app the user navigates by icon shape, not text. Skipping the icon makes the page read as a bare-bones admin tool — and breaks the family resemblance with the rest of the Innexora surfaces.

Primitives

The building blocks. Every more-complex component composes these.

Button

{ Button }

The shadcn Button primitive, rewritten so the default variant carries the brand gradient. Every button in the app comes from here.

Use when: ANY clickable action. Variants: default (primary CTA) · outline (secondary) · ghost (tertiary) · destructive (delete) · secondary (rare). Sizes: default · sm · lg · icon. Lucide icons inside auto-size to h-3.5 w-3.5 with gap-1.5.

Input · Textarea

{ Input, Textarea }

40px hairline-bordered fields with a brand-teal focus ring. Always paired with a .field-label.

Use when: any text/number/date/email field. For multi-line use Textarea (or className="input textarea" on a raw textarea). Disabled state goes paper-cream so it reads as inert without disappearing.

Label

{ Label }

Radix Label primitive, plus the editorial .field-label class for the small uppercase variant.

Use when: inside a <FormSection>, above each input, and on every filter-bar field. The htmlFor attribute keeps clicks on the label focusing the input — accessibility bonus.

Checkbox · Switch

{ Checkbox, Switch }

Radix-driven, restyled to match the editorial language. Switch is for binary settings, Checkbox is for multi-selection.

Use when: Checkbox = "is this true?" inside a form (e.g. Confirmed by tenant). Switch = a setting that flips a feature on/off (e.g. Email notifications).

Selection

Anywhere the user picks one (or one-of-many) value: pills for bounded enums, a hidden-form-select for unbounded picks, segmented controls for view toggles, a date picker for dates.

Horizontal pill row for bounded enums (≤ 10 options). PillGroup is radio-input backed (native form submit). PillButtons is React-state controlled (drives conditional UI).

Use when: Status, Priority, Type, Category, Stage, Condition. Active pill is uniformly brand-indigo-700 with white text in variant="filter", or per-tone in variant="form". For unbounded sets (a stakeholder picker) use HiddenFormSelect.

HiddenFormSelect

{ HiddenFormSelect }

Radix-driven dropdown styled to match the form input language. Writes a hidden input so server-action forms read it natively. NEVER use a raw <select> — it looks generic against the rest of the design.

Use when: the option set is unbounded or large — stakeholder picker, property picker, vendor picker, contract picker.

SegmentedControl · SegmentedControlLinks

{ SegmentedControl, SegmentedControlLinks }

Two-or-three-option toggle. SegmentedControl is React-state controlled, SegmentedControlLinks renders <Link> children so the URL stays the source of truth (good for view toggles like Kanban/List).

Use when: mutually-exclusive view modes. The selected segment carries the same brand-gradient as the primary Button so they read as one brand surface.

DatePicker · Calendar

{ DatePicker, Calendar }

Use when: any date field — start/end dates, expected close, expiry. For date ranges render two DatePickers side by side; the package doesn't ship a custom range primitive (rare enough to not justify one).

KanbanBoard

<KanbanBoard<T> />

Generic drag-and-drop board grouped by a stage column. Used in production for work-orders (six lifecycle stages) and leads (six pipeline stages). The card body is whatever you render via the renderCard prop, so any entity with a "stage" field can drop in.

Use when: the entity has a small, ordered set of stages and the user's most common action is "move from one stage to the next." For pure list browsing (no drag), use the .tbl table instead — paired with SegmentedControlLinks to switch views.

API:

  • stages — { key: string; label: string }[] — column definitions in order
  • items — T[] with id: string and stage: string (or whatever field stageKey points to)
  • renderCard — (item: T) => ReactNode — your card body
  • onMove — (id: string, toStage: string) => void | Promise<void> — server action to call
  • canMove — boolean — gates the drag affordance (cursor-grab, draggable=true). Per-record server check still runs in onMove.
  • cardHref — (item: T) => string — optional, makes each card a navigable link to the detail page

Form helpers

Behaviour primitives that wrap forms — sticky save bar, unsaved-changes guard, confirm-form.

FormSubmitRibbon

{ FormSubmitRibbon }

Sticky bottom bar that tracks form-data dirty state. Shows "No changes" → "Unsaved changes" → spinning "Saving…", with the submit button disabled until something actually changes.

Use when: any long edit form (Property edit, Contract edit, Settings). Wrap the form in this and the save button + dirty hint live in the bottom bar instead of inline.

Unsaved changes

UnsavedChangesGuard

{ UnsavedChangesGuard, useUnsavedChangesGuard }

Hook + component that wires the browser's "you have unsaved changes — leave?" dialog when the form is dirty. Bound to FormSubmitRibbon's dirty state automatically; expose the hook for custom forms.

Use when: any form where data loss on accidental navigation would be painful. Already wired into FormSubmitRibbon — only call the hook directly for hand-rolled forms.

ConfirmForm

{ ConfirmForm }

A small inline confirm-then-submit pattern. Click the button once to "arm" it (turns red); a second click within 3s submits the form. Friction without the heavyweight modal.

Use when: destructive actions inside row context (Delete attachment, Cancel work order). For top-level destructive actions use AlertDialog instead.

export default {
  presets: [preset],
  content: [
    "./app/**/*.{ts,tsx}",
    "./components/**/*.{ts,tsx}",
    "./node_modules/@innexora/ui/dist/**/*.{js,mjs}",
  ],
};

// 3. app/globals.css (Next.js)

Updates propagate via version bump

Whenever a component changes in @innexora/ui:

  1. Edit the component in innexora-ui/src/
  2. Bump version in package.json (semver)
  3. git tag v0.X.Y && git push --tags
  4. In each consumer app: npm install github:KingPotato2023/innexora-ui#v0.X.Y
  5. Deploy. Both apps pick up the change at the same time.
